# 原理与兼容性

## 为什么停用整个鼠标管理器

本机客户端原生代码的 `Torappu.Common.TorappuPCInputHelper._InitWithEventSystem` 会加载鼠标管理器预制体；仅在返回对象非空时实例化并调用 `PCMouseMgr.Init`，为空时继续进行界面缩放、分辨率和键盘设置初始化。

鼠标管理器的 `PCMouseMgr._SwitchStateImpl` 在显示游戏鼠标的分支中，会调用 `UnityEngine.Cursor.set_visible(false)`。因此，单纯让动画或贴图丢失，并不能保证系统指针显示。

本工具的做法是让独立的鼠标管理器资源包暂时不在预期文件名处，从而尝试跳过该管理器的初始化。在最初验证的国服 PC 客户端中，此方法已由使用者实测成功。原生代码还存在自定义硬件指针纹理逻辑；最终指针外观和行为以具体客户端为准。

本工具不依赖“登录界面连续点击开始唤醒”的旧漏洞，也不需要判断动画是否使用 Spine。

## 如何定位资源

工具检查以下目录的 `anon` 和 `mouse` 子目录：

```text
Arknights_Data/StreamingAssets/AB/Windows/
Arknights_Data/PersistentData/Bundles/
```

对候选 `.bin` / `.ab` 及已停用文件读取 UnityFS 头、块描述与压缩数据，以只读方式解码标准 LZ4 和明日方舟的 token / offset 变体，检查序列化路径 `dyn/mouse/pc_mouse_mgr.prefab`。不依赖特定匿名文件名或固定 SHA-256。

不会把全部游戏资源解包到磁盘；检查设置了输入和解码大小上限。不支持的压缩格式、没有目标路径或超出上限的文件不会被修改。

## 可恢复性

启用时，先创建独立备份、验证 SHA-256，再改名原资源。一个安装目录的所有待操作文件会先完成备份；执行过程中出错时尝试回滚已改名文件。记录通过临时文件和原子替换保存。

恢复时，验证停用文件或备份的 SHA-256 和鼠标资源内容。原文件已经存在时保留它。更新后重新启用会生成新的备份记录，旧的备份和停用文件保留。

默认备份按游戏完整路径分组。单实例操作锁防止两个工具进程同时修改同一安装；资源路径检查拒绝目录穿越和资源目录内的链接/联接。

## 验证范围

- 最初实测：国服明日方舟 PC，2026-10-17。
- 本机热更新清单版本：`26-10-14-13-44-12-52990322`。
- 不适用于《明日方舟：终末地》或 Android 模拟器。
- 其他区服、未来更新、不同资源格式或反作弊策略未保证兼容。
- 自动测试使用合成数据；不能代替每个版本的游戏内测试。

如果未来资源加载失败改成强制报错，或初始化流程发生变化，此方法可能失效。应恢复原资源并报告版本，不扩大修改范围。
